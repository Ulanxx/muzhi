## Phase B：文档型付费课程

**核心洞察**：权益/商品/支付/幂等链路对 course 类型**完全通用**——文档课只要仍是 Course 记录，购买、单课权益、幂等发放**零改动复用**。要做的是三个新东西：① 章节内容模型 ② 正文访问控制（付费墙）③ 阅读体验 + 逐章进度。

**你拍板的方向**：章节表 / 页内直接购买 / 逐章进度 / 试读章可 SSR、付费章零泄漏 / 完整闭环。

---

### 一、数据模型（`providers/database/mongodb/models/`）

**1. Course 加 contentType**（`series.ts`，`strict:"throw"` 必须显式加字段）：
```ts
contentType: "video" | "document"   // 默认 "video"，向后兼容，现有课程零迁移
```
枚举值进 `modules/catalog/index.ts` 统一管理（跟 accessLevels 同款风格）。

**2. 新建 CourseChapter 模型**（`models/learning.ts`，跟 CourseMaterial 同文件）：
```ts
CourseChapter {
  courseId: ObjectId ref Course      // 必填，索引
  title: string ≤200
  position: number ≥0                // 排序
  body: string                       // Markdown 正文
  isPreview: boolean                 // true=免费试读章，可 SSR
  timestamps
}
索引 {courseId:1, position:1}
strict: "throw"
```

**3. CourseProgress 扩展阅读进度**（`learning.ts`，现在是视频秒级语义）：
```ts
// 新增可选字段，与现有视频字段并存
readChapterIds: string[]             // 已读章节 id
completed 已有字段复用（全部章节读完=true）
```

**4. 商品配置**：`config/products.config.ts` 加一条文档课商品（`type:"course"` + targetSlug 指向文档课），跟现有 `course-demo-foundations` 同模式。**不改一行 commerce 代码。**

---

### 二、访问控制（付费墙，安全核心）

**原则**：付费章正文必须在 `canCurrentUserAccessCourse` 通过**之后**才从 DB 读出、才进渲染。未授权连 HTML/RSC 流里都查不到一个正文字。参照 `stream/route.ts` 的「404 先行 + 403 在后 + private,no-store」。

**章节正文 API**（新建 `app/api/chapters/[chapterId]/route.ts`）：
- ObjectId 校验 → chapter + course 存在性合并 404（不泄露存在性）
- course 必须 published
- `chapter.isPreview === true` → 直接返回（公开内容）
- 否则 `canCurrentUserAccessCourse(course)` → 不过则 403
- 返回 body + `Cache-Control: private, no-store`

**阅读页渲染分流**：试读章可 SSR（公开营销内容，利于 SEO）；付费章**不在 SSR 输出正文**，客户端挂载后调上面的 API 拉取（已授权则返回，未授权 403 → 渲染付费墙）。

---

### 三、阅读页（`app/learn/[courseId]/page.tsx` 分流）

现有页面假设「课程=视频」。在权限门之后按 `course.contentType` 分流：

- `contentType === "video"` → 走现有 VideoPlayer 路径，**完全不动**
- `contentType === "document"` → 渲染新的 `<DocumentReader>` 组件：
  - 左侧章节目录（position 排序，标注「试读」）
  - 当前章正文：试读章直接 SSR，付费章客户端 API 拉取
  - 上一章/下一章导航
  - 读完一章自动调进度 API 标记该章已读（见四）
  - 杂志编辑部排版：复用 mdx-components 的 h2/h3/code/blockquote 样式

**付费墙组件**（`<PaywallGate>`）：未授权用户看到试读章 + 墙 + 内嵌购买。复用 `CheckoutPanel`，传 `courseId` 让单课商品直达（参考 `pricing/page.tsx` 怎么传 products）。购买成功回调刷新本页 → 解锁全部章节。

---

### 四、逐章进度

**API**：扩展 `app/api/courses/[courseId]/progress/route.ts`：
- 现有视频分支不动（currentTime/duration 校验）
- 新增阅读分支：`{ chapterId, read: true }`，把 chapterId 加进 `readChapterIds`（去重），`readChapterIds.length === 总章节数` 时 `completed=true`
- 同样要求登录 + published + `canCurrentUserAccessCourse`

**模型**：CourseProgress 加 `readChapterIds: string[]`（默认空数组）。唯一索引 `{userId, courseId}` 复用。

**后台可见**：运营后台能看「多少人读完」（复用现有进度查询）。

---

### 五、后台章节编辑

`admin-course-manager.tsx` 增加：
- 建课时可选 `contentType`（视频/文档）
- 文档课出现章节编辑器：章节列表（增/删/上下移）+ 每章 `title + body(Markdown 文本框) + isPreview 开关`
- 调新 API：`POST/PATCH/DELETE /api/admin/chapters`（过 `authorizeAdminMutation`）

**发布校验分支**（`app/api/admin/courses/[courseId]/publish/route.ts`）：
- `contentType==="video"` → 现有「必须有 ready 视频」校验，不动
- `contentType==="document"` → 改为「至少 1 个章节」

### 六、测试（仓库规则：权益必须有测试）

**单测**（`tests/`）：
- 文档课的 `canAccessCourse` 判定（复用现有 entitlement 测试模式，确认 course 权益对 document 课同样生效）
- CourseChapter 排序、isPreview 过滤
- 阅读进度的章节去重与 completed 判定

**E2E**（`e2e/` 新增 document-course.spec.ts，照现有编排）：
1. admin 建文档课 + 3 章（1 试读 + 2 付费）→ 发布（无需视频）
2. 未登录访问：试读章可见，付费章正文 **API 403**、页面出付费墙
3. 注册验证 → 仍无权 → 付费章 403
4. 买单课（mock）→ 幂等授权 → 付费章 API 200、页面可读
5. 标记已读 → 进度 API 返回 readChapterIds；全部读完 → completed=true
6. 直接请求付费章正文 API 无权益 → 403（防裸奔断言）

### 九、明确不做（守住边界）

- ❌ 富文本编辑器（后台用纯 Markdown 文本框，跟博客一致）
- ❌ 章节内嵌视频/图片（Phase C，要走 MediaAsset）
- ❌ 文档课评论/答疑（`FEATURE_COMMENTS=false`）
- ❌ 试读比例自定义（首版只按章节级 isPreview）
- ❌ 逐章单独定价（首版整课一个价）

---

### 十、验收标准

`npm run check` + `release:audit` 全绿；E2E 通过；实测：
1. admin 后台能建文档课、加 3 章、标 1 章试读、发布（无需视频）
2. 未登录看试读章正常，点付费章出付费墙，且直接请求付费章 API 得 403
3. 买单课后全部章节可读，进度逐章标记，读完显示已完成
4. 视频课功能零回归（现有 E2E 照过）

**工作量预估**：模型+访问控制+阅读页+付费墙+后台+测试+ADR，一次性交付一个能真卖文档课的完整功能。
